# AgentSignal 本地 Web 管理界面 · 设计规范

> 版本 v1（2026-09-02，对应 skill-engine 提案 v4 + 裁决 13）
> 读者：前端/全栈工程师。目标：拿本文档零提问开工。
> 范围：`agentsignal` CLI 内置的本地 Web 管理界面（单页 HTML，零外部依赖，由 `node:http` 直接返回）。

---

## 0. 设计原则（先读这五条）

1. **这是一个终端工具的 Web 形态，不是官网。** 气质对齐 shadcn / Base UI / Vercel Dashboard：浅色、克制、信息密度中等偏高，没有任何营销视觉（无渐变 hero、无插画、无 emoji）。
2. **60 秒完成初始化。** 一个页面的认知负担以「新用户不看文档直接走完向导」为验收线。每步只做一件事，文案只说必要的话。
3. **本地信任模型要看得见。** 页头常驻「本地服务 · 仅此电脑」徽章，让用户明确：这个页面跑在自己机器上，提交即关服。
4. **所有数字可追问。** 效率指标注明估算口径；不宣传账单折扣；不承诺「任务完成自动滑出」。
5. **术语红线：全站禁止出现「skills」一词。** 面向用户的措辞只用「能力 / 指引 / 经验」或产品名。代码内标识符不受此限，但任何渲染到界面的字符串必须过一遍红线检查。

## 1. 信息架构

### 1.1 顶层状态机

```
启动 CLI（agentsignal init 或 MCP open_setup）
        │
        ▼
读取并校验本地配置
        │
   ┌────┴─────────────┐
   │                  │
配置不存在/为空     配置存在且合法        配置存在但解析失败
   │                  │                  │
   ▼                  ▼                  ▼
状态 A            状态 B              状态 C（降级态）
初始化向导        管理/状态视图        配置损坏修复页
   │                  │                  │
   │ 提交成功         │ 卸载完成           │ 修复成功 → 状态 B
   ▼                  ▼                  │ 重新初始化 → 状态 A
完成页（静态）   卸载完成页（静态）
   │                  │
   ▼                  ▼
服务自动关闭（页面保持可浏览，不再发请求）
```

### 1.2 状态 A · 初始化向导（页面结构树）

```
Page（状态 A）
├─ Header
│  ├─ Wordmark：AgentSignal
│  └─ Badge：本地服务 · 仅此电脑
├─ StepIndicator（第 1/2/3 步）
├─ StepPanel（同一容器，三步切换）
│  ├─ Step 1 · 业务域
│  │  ├─ StepTitle + StepDesc
│  │  ├─ ChipGroup（常见领域，多选）
│  │  └─ CustomChipInput（自定义输入，回车生成 chip，可删除）
│  ├─ Step 2 · 栈规则
│  │  └─ CheckboxList（默认勾选 Next.js、TypeScript）
│  └─ Step 3 · 宿主接线
│     ├─ DetectedHostList（已探测宿主打 ✓ 置顶，默认勾选）
│     ├─ UndetectedHostList（未探测宿主，可手动勾选）
│     └─ EmptyHosts（一个都没探测到时的提示块）
├─ WizardFooter
│  ├─ Button ghost：上一步（第 1 步隐藏）
│  └─ Button primary：下一步 / 完成并写入配置（最后一步）
├─ FooterBar（常驻底部）
│  └─ Button secondary：使用默认配置直接开始
└─ SubmitOverlay（提交中遮罩：loading → 成功 → 完成页；失败 → 错误提示 + 重试）
```

### 1.3 状态 B · 管理/状态视图（页面结构树）

```
Page（状态 B）
├─ Header（同状态 A）
├─ Section：配置摘要
│  ├─ 业务域（chip 只读列表，空则显示「通用」）
│  └─ 栈规则（已启用项列表）
├─ Section：接线状态
│  └─ StatusRow × N（每个宿主一行：名称 + 状态 ✓ 已接线 / ✗ 未接线 / ⚠ 配置漂移）
├─ Section：本地库
│  └─ 三项数据：条目数 / 索引上次重建时间 / 存储占用
├─ Section：效率指标
│  ├─ MetricCard：吞吐节省
│  └─ MetricCard：残留占用
│  └─ Footnote：估算口径说明
├─ Section：操作
│  ├─ Button secondary：重新运行向导
│  ├─ Button secondary：修复接线
│  └─ DangerZone（红色描边卡片）
│     └─ Button danger：卸载并摘除全部宿主配置 → 弹 DangerDialog
└─ DangerDialog（二次确认弹层，列出将删除的配置文件路径）
```

### 1.4 状态流转（文字描述）

- **A → 完成页**：最后一步点「完成并写入配置」→ 进入提交中 → 全部写入成功 → 渲染完成页 → CLI 关闭 HTTP 服务（页面为静态渲染，不再依赖服务）。
- **A → A（回退）**：任意步可点「上一步」，已填项全部保留在内存中；刷新或关闭页面即丢弃，**不写任何配置**。
- **A → 直通**：底部点「使用默认配置直接开始」→ 弹轻量确认（说明将写入的默认值）→ 提交 → 完成页。等价于 CI `--yes`。
- **B → A**：点「重新运行向导」→ 用现有配置预填向导各步。
- **B → B（修复）**：点「修复接线」→ 对状态为 ✗ / ⚠ 的宿主逐个重写配置 → 行内状态实时更新；全部成功显示成功提示，部分失败列出失败宿主与原因。
- **B → 卸载完成页**：危险区按钮 → DangerDialog 二次确认 → 执行摘除 → 静态完成页 → 服务关闭。
- **C → B / A**：自动修复成功进 B；用户选「重新初始化」进 A（损坏文件先备份为 `<filename>.bak-<时间戳>`）。

## 2. 组件清单

约定：尺寸基于 4px 栅格；所有可交互元素键盘可达；所有交互元素有 `cursor: pointer`（disabled 除外）。

### 2.1 Header

| 项 | 规格 |
|---|---|
| 布局 | 横向 flex，左右两端对齐；高 56px，下边框 1px `--color-border` |
| 左 | Wordmark「AgentSignal」，16px / 600，字距 -0.01em |
| 右 | Badge「本地服务 · 仅此电脑」：绿点 6px + 12px 文案，mono 字体，浅绿底 `--color-success-bg` |
| 变体 | 无。所有状态共用 |

### 2.2 StepIndicator 步骤指示器

| 项 | 规格 |
|---|---|
| 形态 | 三段横向条，每段高 3px，圆角 999px，段间距 4px |
| 当前段 | `--color-primary`；已完成段 `--color-primary` 40% 透明度；未到段 `--color-border` |
| 辅助文案 | 右侧 12px mono：「第 1 步，共 3 步」 |
| 无障碍 | 容器 `role="progressbar"`，`aria-valuenow/min/max` |
| 状态 | 仅展示，无交互 |

### 2.3 Button 按钮

| 变体 | 用途 | 视觉 |
|---|---|---|
| primary | 向导下一步/提交、弹层确认 | 底 `--color-primary`，字 `--color-primary-fg`，13px / 500 |
| secondary | 使用默认直通、B 视图常规操作 | 白底，1px `--color-border-strong`，字 `--color-fg` |
| ghost | 上一步 | 无底无边，字 `--color-muted-fg` |
| danger | 危险区入口 | 白底，1px `--color-danger-border`，字 `--color-danger` |
| danger-solid | 弹层最终确认 | 底 `--color-danger`，白字 |

| 尺寸 | 高度 | 左右 padding | 圆角 |
|---|---|---|---|
| md（默认） | 36px | 16px | `--radius-md` |
| sm | 32px | 12px | `--radius-md` |

| 状态 | 表现 |
|---|---|
| default | 见变体表 |
| hover | primary/danger-solid：亮度 -8%；secondary：底 `--color-hover`；ghost：底 `--color-hover`；过渡 150ms ease-out |
| active | 向下 1px 位移（`translateY(1px)`），无缩放 |
| focus | 2px `--color-ring` 外描边，offset 2px（仅 `:focus-visible`） |
| disabled | 透明度 40%，`cursor: not-allowed`，无 hover |
| loading | 文案前 12px spinner，按钮保持原宽度（文案不换行），禁用点击 |

### 2.4 Chip 选择片（业务域多选）

| 项 | 规格 |
|---|---|
| 尺寸 | 高 32px，padding 0 12px，圆角 999px，13px / 500 |
| default | 白底，1px `--color-border`，字 `--color-fg` |
| hover | 边框 `--color-border-strong` |
| selected | 底 `--color-primary`，字 `--color-primary-fg`，无边框 |
| disabled | 透明度 40% |
| focus | 同 Button focus |
| 语义 | `<button aria-pressed>`，不用 checkbox |
| 自定义 chip | 同 selected 样式，尾部带 12px「×」删除键（独立可聚焦，aria-label「删除 {领域名}」） |

### 2.5 CustomChipInput 自定义输入

| 项 | 规格 |
|---|---|
| 形态 | 与 chip 同高的虚线框输入框（1px dashed `--color-border-strong`），宽 200px，获得焦点时扩展至 240px |
| 占位 | 「输入领域，回车添加」 |
| 行为 | 回车/逗号生成 chip；去重（忽略大小写与首尾空格）；单条 ≤ 20 字，自定义上限 10 条，超限行内提示 |
| 错误态 | 边框 `--color-danger-border`，下方 12px `--color-danger` 文案 |

### 2.6 CheckboxRow 勾选行（栈规则 / 宿主列表共用骨架）

| 项 | 规格 |
|---|---|
| 布局 | 整行可点，高 48px，左右 padding 12px，行间 1px `--color-border` 分隔线（非卡片套卡片） |
| 左 | 16px 自定义 checkbox（选中：底 `--color-primary`，白勾 SVG） |
| 中 | 主文案 14px / 500 + 副文案 12px `--color-muted-fg`（宿主行副文案为 mono 配置文件路径） |
| 右 | 宿主行专属：探测徽标（已探测：绿点 + 「已探测」；未探测：灰点 + 「未探测到」） |
| hover | 底 `--color-hover` |
| checked | 底 `--color-selected-bg`，checkbox 选中 |
| focus | 行级 `:focus-visible` 描边（行内 `tabindex=0`，空格切换） |
| disabled | 透明度 40% |

### 2.7 Panel / Section 面板

| 项 | 规格 |
|---|---|
| 布局 | 白底 `--color-surface`，1px `--color-border`，圆角 `--radius-lg`，padding 20px，面板间距 16px |
| Section 标题 | 14px / 600，字 `--color-fg`，下方 4px 处可放 12px `--color-muted-fg` 说明 |
| 红线 | 面板内不再嵌套带边框的卡片；层级靠分隔线与字重表达 |

### 2.8 StatusRow 接线状态行

| 项 | 规格 |
|---|---|
| 布局 | 同 CheckboxRow 骨架，无 checkbox |
| 状态三态 | ✓ 已接线（绿点 `--color-success`，字「已接线」）；✗ 未接线（灰点 `--color-neutral-400`，字「未接线」）；⚠ 配置漂移（琥珀点 `--color-warning`，字「配置漂移」） |
| 副文案 | mono 12px 配置文件路径，过长中段省略（`…/settings.json`），完整路径放 `title` |
| 漂移附加 | ⚠ 行尾部 inline 按钮 sm secondary：「修复此行」 |

### 2.9 MetricCard 指标卡（效率指标，双卡分列）

| 项 | 规格 |
|---|---|
| 布局 | 两列等宽 grid（≥1024px），窄窗口折为单列；Panel 内不嵌边框卡，用左粗细分隔线区分两卡 |
| 数值 | 28px / 600，mono，字 `--color-fg`，千分位分隔 |
| 单位 | 数值后 13px `--color-muted-fg`：「tokens（估算）」 |
| 名称 | 13px / 500：「吞吐节省」/「残留占用」 |
| 说明 | 12px `--color-muted-fg`，一行：见文案表 C-20/C-21 |
| 口径注 | 两卡下方通栏 12px `--color-subtle-fg`：「按 bytes ÷ 4 估算 token 数，仅为量级参考，不代表账单金额」 |

### 2.10 Alert 行内提示条

| 变体 | 用途 | 视觉 |
|---|---|---|
| info | 中性说明 | 左 2px `--color-neutral-400` 竖条，底 `--color-neutral-50` |
| success | 操作成功 | 左 2px `--color-success`，底 `--color-success-bg` |
| error | 操作失败 | 左 2px `--color-danger`，底 `--color-danger-bg`，正文 13px `--color-danger-fg` |

- 统一圆角 `--radius-md`，padding 10px 12px，右侧可放 inline 操作（如「重试」）。
- 出现时不做布局推挤之外的动效；`role="alert"`（error）/ `role="status"`（info/success）。

### 2.11 SubmitOverlay 提交遮罩

| 项 | 规格 |
|---|---|
| 形态 | 全页半透明遮罩（`rgb(255 255 255 / 0.72)` + 4px 模糊），居中 280px 宽白卡 |
| loading | spinner 20px + 「正在写入配置…」 |
| error | Alert error 变体内嵌：错误原因 + Button primary sm「重试」+ Button ghost sm「返回修改」 |
| 成功 | 不显示成功卡，直接过渡到完成页（200ms 淡出） |

### 2.12 DangerDialog 危险确认弹层

| 项 | 规格 |
|---|---|
| 尺寸 | 宽 440px（窄窗 92vw），圆角 `--radius-lg`，padding 24px |
| 遮罩 | `rgb(0 0 0 / 0.32)`，点遮罩不关闭（防误触），仅「取消」与 Esc 可关 |
| 结构 | 标题 16px / 600 `--color-danger` → 说明 13px → 将删除文件列表（mono 12px，灰底，最多显示 8 条，超出滚动）→ 知情复选框「我了解此操作不可撤销」→ 按钮行 |
| 按钮 | 右对齐：ghost「取消」（默认聚焦）+ danger-solid「卸载并摘除配置」（复选框未勾选时 disabled） |
| 键盘 | 打开即 trap focus；Esc = 取消 |

### 2.13 其余元件速查

| 元件 | 规格 |
|---|---|
| Spinner | 12/20px 两档，2px 描边 `--color-border`，弧 `--color-primary`，0.8s 线性旋转（reduced-motion 下改为三点脉冲） |
| FooterBar 常驻栏 | 吸底，高 64px，上边框 1px `--color-border`，底 `--color-surface` 95% + 模糊 8px；居中容器内放 secondary 按钮 + 12px 说明 |
| 空态 EmptyState | 面板内居中：13px `--color-muted-fg` 一句说明 + 可选一个 sm secondary 操作；无插画、无 emoji |
| Divider | 1px `--color-border`，上下间距 16px |
| 徽标 Badge | 高 20px，圆角 999px，12px mono，绿/灰/琥珀三态（同状态点色板） |

## 3. 交互与反馈

每个动作按「前置条件 → 执行反馈 → 成功 → 失败分支」描述。

### 3.1 向导 · 下一步

- **前置**：当前步校验通过。第 1 步：至少保留 0 个领域（允许全不选，语义为「通用」）；第 2 步：允许 0 项启用；第 3 步：允许 0 个宿主（见边界情况 E-1）。
- **执行**：点击 → StepIndicator 推进，StepPanel 横移 12px + 淡出/淡入（150ms ease-out，reduced-motion 下仅透明度过渡）。
- **失败**：校验不过时按钮保持可点，点击后在出错组件旁显示行内错误并聚焦首个错误项。

### 3.2 向导 · 上一步

- **前置**：第 2、3 步可见。
- **执行**：所有已填项（含自定义 chip、勾选态）从内存恢复，不做任何写盘。

### 3.3 向导 · 完成并写入配置

- **前置**：三步均已访问过（直通检查，防止漏步）。
- **执行**：按钮进入 loading，SubmitOverlay 出现。
- **成功**：渲染完成页 → CLI 关闭服务。完成页静态可浏览。
- **失败**：Overlay 切 error 态：中文原因（写入权限不足 / 磁盘错误 / 宿主配置被占用等）+「重试」（重新提交）+「返回修改」（回到第 3 步，数据不丢）。**原子性**：所有文件先写临时文件再 rename，任一失败则全部回滚，界面明确告知「未写入任何配置」。

### 3.4 使用默认配置直接开始（FooterBar）

- **前置**：状态 A 任意步。
- **执行**：点击 → 按钮 loading → 直接提交默认值（业务域=通用；栈规则=Next.js + TypeScript；宿主=全部已探测项）。
- **成功 / 失败**：同 3.3。
- **说明文案**常驻按钮右侧，12px：「跳过向导，写入推荐配置」。

### 3.5 中途关闭页面

- 不写任何配置；不弹挽留提示（本地工具，无此必要）。CLI 侧按自身策略退出或等待，与界面无关。

### 3.6 B 视图 · 修复接线

- **前置**：存在状态为 ✗ 或 ⚠ 的宿主；全部 ✓ 时按钮 disabled，附 12px 说明「所有宿主接线正常」。
- **执行**：按钮 loading，逐个重写异常宿主的配置；每个 StatusRow 状态实时从 ⚠/✗ 翻转为 ✓（150ms 颜色过渡）。
- **成功**：顶部 Alert success：「接线已修复，共处理 N 个宿主」。
- **失败**：Alert error 列出失败宿主与原因（如「Cursor：配置文件被其他进程占用」），按钮恢复可点，可再次执行；已修复行不回滚。

### 3.7 B 视图 · 重新运行向导

- **执行**：跳转状态 A，现有配置预填（业务域/栈规则回显，已接线宿主默认勾选）。
- **提交后**：走 3.3 流程。

### 3.8 危险区 · 卸载并摘除全部宿主配置

- **前置**：无（任何接线状态都可卸载）。
- **执行**：点击 → DangerDialog 打开，文件列表由 CLI 实时扫描给出（与将删除内容一一对应）。
- **确认**：勾选知情复选框 → 确认按钮可点 → loading → 摘除完成 → 渲染卸载完成静态页 → 服务关闭。
- **失败**：Dialog 内 Alert error 列出删除失败的文件与原因（权限不足等），提供「重试」与「取消」；已删除部分不回滚，列表实时剔除已删除项。

### 3.9 状态 C · 配置损坏

- **进入条件**：启动时配置解析失败。
- **页面**：Panel 显示错误摘要（文件名 + 行号 + 解析错误原文 12px mono）+ 两个操作：primary「尝试自动修复」、secondary「重新初始化」。
- **自动修复**：尝试修复 JSON 语法 → 成功进 B；失败则更新错误摘要，secondary 保持可用。
- **重新初始化**：损坏文件备份为 `.bak-<时间戳>` 后进状态 A，页面顶部 Alert info 告知备份路径。

### 3.10 全局反馈规则

- 所有异步操作必须有 loading → 成功/失败三态；成功反馈 3s 后自动淡出（error 不自动消失）。
- 反馈文案用 `aria-live="polite"` 区域播报（error 用 `assertive`）。
- 同一操作 1s 内重复点击只触发一次（按钮 loading 即天然防抖）。

## 4. 文案表

## 5. 视觉 Tokens

以 CSS 自定义属性给出，全部内联在单 HTML 的 `<style>` 中。浅色主题唯一，不做暗色模式。

### 5.1 色板

```css
:root {
  /* 中性阶（zinc 系，工具感基调） */
  --color-neutral-50:  #FAFAFA;
  --color-neutral-100: #F4F4F5;
  --color-neutral-200: #E4E4E7;
  --color-neutral-300: #D4D4D8;
  --color-neutral-400: #A1A1AA;
  --color-neutral-500: #71717A;
  --color-neutral-600: #52525B;
  --color-neutral-900: #18181B;

  /* 语义映射 */
  --color-bg:            var(--color-neutral-50);   /* 页面底 */
  --color-surface:       #FFFFFF;                   /* 面板/输入底 */
  --color-fg:            var(--color-neutral-900);  /* 主文字 */
  --color-muted-fg:      var(--color-neutral-600);  /* 次要文字 */
  --color-subtle-fg:     var(--color-neutral-500);  /* 辅助/注脚文字 */
  --color-border:        var(--color-neutral-200);  /* 默认描边 */
  --color-border-strong: var(--color-neutral-300);  /* hover/输入描边 */
  --color-hover:         var(--color-neutral-100);  /* 行/按钮 hover 底 */
  --color-selected-bg:   var(--color-neutral-100);  /* 勾选行底 */

  /* 主操作（近黑，终端工具签名色） */
  --color-primary:    #18181B;
  --color-primary-fg: #FAFAFA;
  --color-ring:       #18181B;

  /* 状态色（低饱和，只用于点、细条、小徽标，不大面积铺色） */
  --color-success:      #16A34A;
  --color-success-bg:   #F0FDF4;
  --color-warning:      #D97706;
  --color-warning-bg:   #FFFBEB;
  --color-danger:       #DC2626;
  --color-danger-fg:    #B91C1C;
  --color-danger-bg:    #FEF2F2;
  --color-danger-border:#FECACA;

  /* 遮罩 */
  --overlay-light: rgb(255 255 255 / 0.72);
  --overlay-dark:  rgb(0 0 0 / 0.32);
}
```

对比度校验：`--color-fg` on `--color-surface` ≈ 16.1:1；`--color-muted-fg` on 白 ≈ 7.5:1；`--color-subtle-fg` on 白 ≈ 4.6:1（仅用于 12px 注脚，达标 4.5:1）；`--color-primary-fg` on `--color-primary` ≈ 16.1:1；`--color-danger-fg` on `--color-danger-bg` ≈ 5.9:1。全部 ≥ WCAG AA 4.5:1。

### 5.2 字体与字阶

零外部字体。中文正文走系统栈，数字/路径/端口/字节走等宽栈——等宽数字是这个界面的签名细节。

```css
:root {
  --font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI",
               "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei",
               "Noto Sans CJK SC", sans-serif;
  --font-mono: ui-monospace, "SF Mono", SFMono-Regular, Menlo,
               Consolas, "Liberation Mono", monospace;

  /* 字阶（基准 14px，工具密度） */
  --text-xs:   12px;  /* 注脚、副文案、徽标；行高 1.5 */
  --text-sm:   13px;  /* 按钮、chip、说明；行高 1.5 */
  --text-base: 14px;  /* 正文、列表主文案；行高 1.5 */
  --text-md:   16px;  /* 步骤标题、Section 强调；行高 1.4 */
  --text-lg:   18px;  /* 页面主标题；行高 1.35 */
  --text-num:  28px;  /* 指标数值（mono）；行高 1.2 */

  --weight-regular: 400;
  --weight-medium:  500;
  --weight-strong:  600;
}
```

规则：中文不设置 `font-style: italic`（机械伪斜体）；强调用字重或颜色。mono 仅用于：文件路径、数字指标、端口/地址徽标、错误原文。

### 5.3 间距 / 圆角 / 描边 / 阴影

```css
:root {
  --space-1: 4px;  --space-2: 8px;   --space-3: 12px;

}
```

### 5.4 动效 tokens

```css
:root {
  --dur-fast: 120ms;  /* hover、chip 切换 */
  --dur-base: 150ms;  /* 按钮、行状态翻转 */
  --dur-slow: 200ms;  /* 面板切换、遮罩淡入淡出 */
  --ease-out: cubic-bezier(0.2, 0, 0, 1);
}

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    transition-duration: 0.01ms !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
  }
}
```

规则：只用 `opacity` 与 `transform` 做过渡属性；不做 scroll-triggered 动效；spinner 是唯一持续动画（reduced-motion 下替换为三点脉冲）；弹层进入 = 透明度 0→1 + `translateY(4px)→0`，退出快于进入（120ms / 200ms）。

## 7. 边界情况与降级

| 编号 | 场景 | 界面行为 |
|---|---|---|
| E-1 | 探测不到任何宿主 | 第 3 步宿主区替换为 EmptyState：「未在这台电脑上探测到已知宿主。可以手动勾选下方宿主按默认路径写入，或直接跳过。」下方仍列出全部可选手动项；允许 0 勾选提交，完成页走 F-04 替代行。 |
| E-2 | 全默认直通 | FooterBar 按钮一键提交默认值（业务域=通用、栈规则=Next.js + TypeScript、宿主=全部已探测项），流程与 3.3 一致；与 CI `--yes` 完全等价，无额外确认弹层（按钮旁常驻说明已尽告知义务）。 |
| E-3 | 端口被占用 | 属 CLI 层：随机端口绑定失败时重试新端口（最多 3 次）；仍失败则终端输出 URL 与「请手动在浏览器打开」指引。页面本身无特殊态。 |
| E-4 | 配置文件被外部改坏 | 启动校验失败进入状态 C（见 3.9）：显示文件名 + 行号 + 解析错误，提供「尝试自动修复」「重新初始化」；重新初始化前自动备份为 `.bak-<时间戳>`。 |
| E-5 | 卸载二次确认 | 见 2.12 / 3.8：弹层 + 文件清单 + 知情复选框 + danger-solid 按钮，四重缓冲；点遮罩不关闭。 |
| E-6 | 提交原子性 | 所有配置先写临时文件再原子 rename；任一失败全部回滚，界面明示「未写入任何配置」。 |
| E-7 | 中途关闭页面 | 不写任何配置，不弹挽留；向导数据仅存内存。 |
| E-8 | 提交成功后用户刷新页面 | 服务已关闭，浏览器显示连接失败属预期；完成页 F-07 已提前告知。 |
| E-9 | 窄窗口（360px） | 容器 padding 收至 16px；指标双卡折单列；宿主行副文案路径中段省略；弹层 92vw；不出现横向滚动。 |
| E-10 | 宿主配置文件需要合并而非覆盖 | 提交失败分支 E-04 文案覆盖：提示备份后重试；不静默覆盖用户已有的宿主配置。 |
