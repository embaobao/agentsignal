## 一、总纪律：尽量支持，不支持的全兼容

> **一句话**：**能力在任一宿主上、任一环节不可用，都必须降到下一档继续可用，而不是报错、更不是静默丢弃。每次降级都要能被用户看见。**

### 1.1 三档落地阶梯（任何能力 × 任何宿主）

| 档 | 条件 | 落地方式 | 效果 |
|---|---|---|---|
| **L1 原生** | 宿主有该能力位（技能目录 / rules / hooks / MCP） | 写进宿主**原生位置** | 宿主原生可见，常驻 context |
| **L2 按需** | 无能力位，但有 MCP | 经我方九工具按需可达（`search_skills` / `load_skill_detail`） | 对话内可达，**不常驻 context** |
| **L3 兜底** | 两者皆无 | rules 写一行提示（"本机能力经 agentsignal 查询"） | 仅提示，能力不落地 |

**三条硬纪律**：

1. **降到底仍有档**：L1→L2→L3 逐级下探；**取不到任何一档才允许报错**
2. **降级必须可见**：`status` 呈现「某能力在某宿主落在第 N 档」，并提供原因（如"该宿主无 skills 位"）
3. **降级不得改变语义**：不许因为降级就让 Agent 以为"我没有这个能力"——L3 也要留下可检索的入口

### 1.2 各维度的降级矩阵

| 维度 | 尽量支持 | 不支持时 |
|---|---|---|
| **宿主能力位** | 有 skills 位 → 直写 | 无 skills 位但有 MCP → 落 L2；两者皆无 → L3 |
| **宿主配置格式** | JSON（多数） | TOML（Codex）· YAML（Hermes）**各写各的原生格式**；写不了的宿主 → **跳过并告警**（不静默） |
| **字段映射** | 全字段可写 | 目标格式不认识的键 → **丢弃 + 告警**（沿用 APM 实测做法：`keys ... were dropped`） |
| **引用方式** | symlink（更新自动跟随） | 跨卷 / Windows → **回退 copy**；账本记 `mode`，对账按 mode 分支 |
| **界面载体** | MCP Apps（对话内渲染） | 宿主不支持 → **拉起本地网页**（单文件 HTML，`127.0.0.1`，用完即关）→ 再退 `status` 文本 |
| **外部工具** | APM 适配器可用 | 未装 APM → **native 适配器**；两者皆不可用 → **只读模式**（能查不能装） |
| **记忆** | 下发给支持的宿主 | 不支持 → **留在本地库**，仅经 MCP 按需可查 |
| **常驻** | 包显式声明常驻 | 未声明 → **按需拉起** |
| **包源** | git / npm / 本地路径 | APM 包 → 经 apm 适配器；任何单一源不可达 → **换源重试，不中断整体** |
| **提示词/注入段** | 有注入位 → 直写 | 无 → **合并进 rules**（不丢内容） |

**总原则的由来**：APM 实测中已见其护栏（`[i] Skipped MCP config for claude, codex (active targets: copilot)`、frontmatter 键丢弃告警）。**我们照此办理，但增加"降级阶梯"这一层——不在无法落地时简单跳过，而是下探到还能用的那一档。**

## 三、数据结构

### 3.1 `agents.json`（包自带清单）

```jsonc
{
  "schema": "agentsignal.package/v1",
  "name": "<pkg_name>",
  "version": "1.2.0",

  // ── 标准段：对齐 apm.yml 语义，零工具可读 ──────────────────
  "apm": {                       // 对齐映射，导出时直出
    "name": "<pkg_name>",
    "version": "1.2.0",
    "targets": ["claude", "cursor"],
    "dependencies": { "apm": [], "mcp": [] }
  },

  // ── 内容段 ────────────────────────────────────────────────
  "skills":  [{ "id": "<sig_id>", "path": "skills/<name>" }],
  "mcp":     [{ "name": "<mcp_id>", "transport": "stdio|http", "command": "...", "args": [] }],
  "prompts": [{ "path": "prompts/<name>.md" }],
  "rules":   [{ "path": "rules/<name>.md" }],

  // ── 扩展段：私有增强，不进标准产物（开放，给后续留口子）────
  "extensions": {
    "agentsignal": {
      "capability_ladder": "L1",     // 期望档位（实际档位由运行时探测决定）
      "residency": "on-demand",      // on-demand | resident
      "min_validation": "self-tested",
      "memory": null                 // 预留（P6）
    }
  }
}
```

### 3.2 `ledger.json5`（归属账本）

```jsonc
{
  "schema": "agentsignal.ledger/v1",
  "entries": [{
    "pkg_id": "<pkg_id>",
    "adapter": "apm" | "native" | "pi" | "dsh" | "<community>",
    "host": "claude",
    "mode": "link" | "copy",            // ★ 决定对账口径
    "ladder": "L1" | "L2" | "L3",       // ★ 实际落在哪一档
    "items": ["skills/<name>", "..."],  // 委托内容
    "snapshot": [{ "path": ".claude/skills/x/SKILL.md", "sha256": "..." }],  // ★ 委托快照
    "at": "2026-09-11T17:03:00Z"
  }]
}
```

**为什么要快照**：账本只记"委托给谁"，一旦适配器缺席/被卸载就会失效。快照让账本**自足**——没有适配器也能回答"当时装了什么"。

### 3.3 `skill.json5` 扩展（最小改动）

```diff
  {
    "id": "<sig_id>",
    "version": "1.2.0",
    "dependencies": { "env": [], "bins": [], "packages": [] },
    "provenance": { "origin": "<source>", ... },   // ★ origin 补写入（P5）
-   "verify_target": null,
+   "verify_target": { "statement": "...", "checks": [] }   // ★ 补实现（P5）
  }
```

## 四、接口契约

```ts
// ── A 段：包从哪来 ────────────────────────────────────────
export interface PackageSource {
  id: string;                                          // "git" | "npm" | "apm" | "local"
  probe(): Promise<Availability>;
  resolve(ref: PackageRef): Promise<PackageMetadata>;
  fetch(ref: PackageRef): Promise<Package>;
}

// ── B 段：装到哪、装得对不对 ──────────────────────────────
export interface CapabilityAdapter {
  id: string;                                          // "native" | "apm" | "pi" | "dsh" | ...
  probe(): Promise<Availability>;                      // { available, version?, reason? }
  capabilities(): ReadonlySet<Cap>;                    // ★ 未声明 = 不得调用
  hosts(): readonly HostId[];
  deploy(items: PackageItem[], host: HostId): Promise<DeployResult>;
  remove(items: PackageItem[], host: HostId): Promise<RemoveResult>;
  reconcile(): Promise<ReconcileReport>;               // ★ 硬要求
}

export type Cap =
  | "skill" | "mcp" | "prompt" | "rule"
  | "deploy" | "remove"          // 分开声明：APM 有 deploy 无 remove
  | "audit" | "runtime" | "switch";

export interface DeployResult {
  host: HostId;
  ladder: "L1" | "L2" | "L3";        // ★ 实际落档
  written: string[];
  skipped?: { target: HostId; reason: string }[];   // ★ 降级/跳过必须带原因
  warnings?: string[];               // ★ 丢弃字段等一律告警
}
```

**门控与锁**：

```ts
// 能力门控：未声明直接拒绝（结构化错）
if (!adapter.capabilities().has("remove"))
  throw new UnsupportedCapability({ adapter: adapter.id, cap: "remove" });

// 归属锁：一宿主 + 一能力 = 一适配器
acquireHostLock({ host: "claude", cap: "skill" }, adapter.id);
// 冲突 → HostLockConflict（含持锁方与建议）
```

## 六、关键实现要点

| # | 要点 | 做法 |
|---|---|---|
| 1 | **原子写** | 一律 `tmp + rename`；索引同步沿用既有做法 |
| 2 | **并发** | 沿用"约定不靠锁"（一宿主一实例）；账本写入加**文件级互斥** |
| 3 | **幂等** | `deploy` 重复执行结果一致；`remove` 对不存在项静默成功 |
| 4 | **卸载对等** | 只删账本 `items` 内条目；**摘除不残留**（含空目录清理） |
| 5 | **不碰他人** | 只写账本内条目；`reconcile` 扫全部但**外来条目只读** |
| 6 | **规则归一** | 宿主名、路径一律小写归一（对齐 APM 的 case-insensitive 规则） |
| 7 | **降级可观测** | 每次 `deploy` 把 `ladder` + `skipped[].reason` 写回账本 |

## 八、验收闭环终态（★ 本节是"最后结果"的定义）

### 8.1 闭环全链路（七步）

```
① 平台       一个 solution 被发布
      ↓ 订阅同步
② 本地       落库成技能（带 provenance + verify_target）
      ↓ 适配器装载（L1→L2→L3 阶梯）
③ 宿主       Agent 原生可见/可用（或降至按需/兜底）
      ↓ 真实使用
④ 留痕       记录：被检索 / 被注入 / 被加载 / 被使用
      ↓ 验证
⑤ 判定       对 verify_target 给出三态（好用 / 一般 / 没用）+ 可选 evidence
      ↓ 回流
⑥ 平台       验证被聚合（计数 · 分布）
      ↓ 反哺
⑦ 本地       拉回聚合数字（不拉明细）→ 用户看到"别人用得好不好"
```

**今天断在第 ③ 步。** 本线（P0–P5）就是把 ③ 接通，并把 ④⑤ 从"半通"补成"通"。

### 8.2 终态断言（可执行的验收口径）

> 在**一台从未装过 AgentSignal** 的机器上：

| # | 断言 | 通过标准 |
|---|---|---|
| **A1** | 接入一个**支持 L1** 的宿主（如 Claude Code） | 该能力**原生出现**，且**全程没有人工复制任何文件** |
| **A2** | 该宿主的 Agent 在此能力下真实完成一次任务 | 任务成功；`sessions/` 有留痕 |
| **A3** | 完成后给出判定 | 三态之一被记录，且能关联回上游信号 |
| **A4** | 跑 `status` | 一次性看到：**已落地 · 落档 · 用过 N 次 · 最近判定 · 上游信号** |
| **A5** | 卸载 | 宿主目录**零残留**；**本地库仍保留**（经验不删） |
| **A6** | 在一个**不支持 L1** 的宿主上重做 A1–A3 | **自动落到 L2**，且 `status` 明确显示"已降至按需档 + 原因" |
| **A7** | 在**未装 APM** 的机器上重做 A1 | 走 native 适配器，**不报错**；装上 APM 后仍正常 |

**一句话验收**：

> **一个真实 Agent，在没人帮它复制任何文件的情况下，装上方案包就能用上，用完能说好不好，这个说法还能回到平台上被别人看到。**

这就是【experience.md 幕二】「`use` → 长出 SKILL.md → 装进技能目录 → 照 What worked 执行 → 成功」的**可执行化**，并向外延伸到回流。

### 8.3 闭环终态要回答的三个问题（现状 vs 终态）

| 问题 | 现状 | 终态 |
|---|---|---|
| 宿主实际有哪几条能力？ | ❌ 答不了 | ✅ `reconcile` 五态 + `status`（含外来只读） |
| 这条经验被用过吗、结果如何？ | ⚠️ 半通（无 evidence、`verify_target` 空转） | ✅ 三态 + 目标闭环 + 留痕 |
| 别人用得好不好？ | ❌ 看不到 | ✅ 聚合数字回流（不拉明细） |

### 8.4 分层验证目标（验证金字塔）

| 层 | 名称 | 覆盖内容 | 何时跑 |
|---|---|---|---|
| **V0** | 契约 | 每适配器四方法（`probe/deploy/remove/reconcile`）× 能力门控 × 归属锁；**降级矩阵（§1.2）每行一个"不支持"夹具**，断言落到下一档且原因可见 | 每 PR |
| **V1** | 集成 | `AGENTSIGNAL_HOME` 夹具内全链（**绝不碰真实宿主配置**） | 每 PR |
| **V2** | 真机 | **A1–A7**（黄金路径 + 两类降级 + 卸载对等） | 每期出口 |
| **V3** | 闭环 | **S3 全链**——本地半 = P5 出口；**平台半（聚合/反哺）= 服务端后续提案，不在本线** | 里程碑 |
| **V4** | 回归 | 旧技能零破坏 · 5 宿主接线 · 九工具面 · G1–G4 护栏 | 每期出口 |

### 8.5 场景验证矩阵（S1–S10）

| # | 场景 | 前置 | 通过标准 | 层 |
|---|---|---|---|---|
| **S1** | **黄金路径**：全新机器首次接入 | 未装过 AgentSignal；一个 L1 宿主；平台有一条 solution | 订阅→同步→装载→Agent 使用，**全程无人工复制**；sessions 留痕 | V2/V3 |
| **S2** | **使用留痕** | S1 完成 | 被检索 / 被注入 / 被使用**分别计数**（现状：`use_count` 只在 verify 时 +1 —— **P5 需修**，拆 `retrieved/injected/used` 三计数） | V1/V2 |
| **S3** | **验证与回流（闭环终点）** | S2 完成 | 本地半：三态判定可记录、可关联回上游信号；平台半：聚合数字回流（**另立，见 V3**） | V3 |
| **S4** | **卸载 / 重装 / 多宿主** | 同一能力装 3 个宿主 | 卸 A 不影响 B；卸后宿主**零残留**、本地库保留；重装恢复 | V2 |
| **S5** | **降级：无 L1 宿主** | 只有 MCP、无 skills 位的宿主 | 自动落 L2；`status` 显示落档 + 原因；**不报错** | V2 |
| **S6** | **降级：未装 APM** | 无 APM 的机器 | native 接管不报错；**装上 APM 后仍正常**（不双写冲突） | V2 |
| **S7** | **漂移与对账** | 用户手改宿主技能目录 / 别的工具装了东西 | `reconcile` 五态正确；**外来条目 `foreign` 只读**；我方条目可修复 | V1/V2 |
| **S8** | **适配器冲突** | 两个适配器争同一宿主同一能力 | 归属锁拒绝 + 结构化错（含持锁方与建议） | V0 |
| **S9** | **更新链** | 上游 solution 更新 | symlink 模式自动跟随；copy 模式重写；`UPDATES.md` 追加不覆盖 | V1 |
| **S10** | **互操作往返** | 导出 `apm.yml` → 再导入 | 标准部分往返无损；**私有元数据零泄漏进产物** | V1 |
| **S11** | **模型接入** | 宿主 + 供应商注册表 | env 写入 → 宿主经国产端点跑通 → 切换供应商 → 快照回滚恢复；**token 不进产物/导出** | V2 |
| **S12** | **面板扩展** | B 视图 + 夹具数据 | 四新区块数据断言 · 全站无「skills」· 降级落档可见 | V1 |
| **S13** | **运行时拉起** | git / npm 包源 | 按需拉起 Agent → 用完即退（**无常驻**）；账本记条目 | V2 |
| **S14** | **依赖管理** | `skill.json5` dependencies | 预检告警 · 显式安装 · **白名单外拦截** · origin=npm-install | V1/V2 |
| **S15** | **动态加载** | pi（热切）/ 其他宿主 | 支持者热切换；不支持者降级（重载/提示）且可见 | V2 |
| **S16** | **分 Agent 管理** | 两宿主各配不同技能集 | 独立准入 / 计数 / 卸载**互不影响** | V1/V2 |

> **S2 是本轮场景分析新发现**：现有 `use_count` 只在 verify 时递增，"被检索/被注入"不计——**使用留痕（闭环第 ④ 步）目前是缺的**，须并入 P5 一起修（与 `verify_target` 同期）。

### 8.6 完整预期（做完 P0–P8 后；P7/P8 为 2026-09-11 增补）

**✅ 为真（可验收）**：
1. 黄金路径通——**没人帮 Agent 复制任何文件**，能力装上就能用（S1）
2. 任何宿主 / 任何环境**不报错**——降到底仍有档，且看得见为什么（S5/S6）
3. `status` 一览全局——装了什么 · 在哪 · 第几档 · 用过几次 · 最近判定 · 上游是谁（A4）
4. 拆得干净——宿主零残留、本地库保留、多宿主互不影响（S4）
5. 用完能说好不好——三态判定 + 目标 + 留痕可关联上游（S2/S3 本地半）
6. 别人的工具能读我们的产物、我们的账本扛得住外部漂移（S7/S10）

## 十三、执行范式：夜间七席流水线（2026-09-11 定档 · 当日扩编）

**约束**：23:00 后免额窗口 → **全部开发会话排夜间**（白天零运行，不花额度）；会话模型为 flash 档 → **任务小颗粒 + 强处方 + 多维审查**兜底。

| 席 | 时间 | 轨道 | 职责 | 并发 |
|---|---|---|---|---|
| 主轨开发 | 23:00 | A：P0→P1→P2→P3 | 取任务 → 实现 → 测试 → commit | 写·串行 |
| 副轨开发 | 01:00 | B：P5→P4→P7→P8 | 同上（文件域隔离） | 写·串行 |
| 基建轨 | 03:00 | C：验证工程与基建 | 场景壳 / 契约套件 / 台账脚本 / 性能基线 / 手册 | 写·串行 |
| 审查·规范 | 05:00 | 全局 | DoD 与台账一致性 → `reviews/<date>-dod.md` | 读·**并行** |
| 审查·测试 | 05:00 | 全局 | 测试真实性与覆盖 → `reviews/<date>-test.md` | 读·**并行** |
| 审查·红线 | 05:00 | 全局 | 安全与红线七条 → `reviews/<date>-redline.md` | 读·**并行** |
| 汇总修复 | 06:30 | 全局 | 合并三报告 → 定稿 `tasks.md` + 修复 + 全量 verify | 写·串行 |

**并发原则（为什么这么切）**：
- **写必须串行** —— 同仓并行提交会撞 `git index.lock`，同文件并行编辑会互相覆盖（flash 档更易发生）
- **读可以并行** —— 审查只写各自独立报告文件；且**审查席不做 git 写操作**，由汇总席统一提交，读席之间零冲突
- **验证能力靠"多维度"而非"多写手"扩展** —— 3 个审查维度（规范 / 测试 / 红线）比 3 个写手更能保质量

**兼容降级（并发不足时尽量多做）**：全开 → 单读席内 spawn 三只读子代理 → 顺序过三遍清单 → 缩窗保写轨 + 次日补审。
**硬约束**：**任何降档都不取消审查**（质量门不可跳过，只能压缩维度或延后）。

**质量闭环**：任务完成 = 开发 commit + **三审通过**双签；任一审查席 🔴 → 回 `[~]` 带原因 → 当夜汇总席修复。
**溢出 / 失败 / 模板**：见 [tasks.md](tasks.md) §〇 与 [templates.md](templates.md)。
