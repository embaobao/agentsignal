## 一、场景测试模板（S 断言落为 node:test 时用此骨架）

```ts
test("S5: 无 L1 宿主 → 自动落 L2 且可见", async () => {
  const home = await fixture();                        // ① 前置：AGENTSIGNAL_HOME 临时目录
  const host = fakeHost({ skillsPath: null, mcp: true }); // ① 前置：构造"不支持"环境
  const r = await deploy(pkg, host);                   // ② 动作
  assert.equal(r.ladder, "L2");                        // ③ 通过标准：对照 design §8.5 表格逐条
  assert.ok(r.reasons?.length, "降级必须带原因");
});
```

**四要素**：① 前置（夹具构造"设计好的不支持"）→ ② 动作 → ③ 通过标准（照抄 design §8.5 该行）→ ④ 层标注（V0/V1 在文件头注释）。
**夹具红线**：只用 `AGENTSIGNAL_HOME` 临时目录，**绝不读写真实宿主配置**。

## 四、审查清单（04:00 席逐项过）

| # | 审项 | 通过标准 |
|---|---|---|
| 1 | **DoD 逐条** | 任务行每条 DoD 都能在 diff / 测试中指出对应物 |
| 2 | **红线七条** | 九工具面不变 · 零触碰 apps/api · Zero-LLM · 写只碰自己条目 · 不新增常驻/微服务/K8s · 不碰真实宿主配置 · 不引入 LLM 调用 |
| 3 | **测试真实** | 新增测试文件存在、断言非空、本地跑过（看输出非猜测） |
| 4 | **勾选一致** | tasks.md 勾选 = 提交信息含该任务编号 |
| 5 | **降级可见** | 涉降级路径必有 `reason` 输出，无静默跳过 |
| 6 | **工作区干净** | `git status` 无未提交改动 |
| 7 | **交接合规** | `[~]` 任务必有交接/失败注记 |

**产出格式**（写进会话汇报 + tasks.md 审查结论）：

```
📋 审查报告 · 2026-09-12 夜
✅ 通过：0.1 0.2 5.1（DoD 齐 · 红线过 · 测试实）
🔴 驳回：x.y —— 原因（任务已回 [~]）
🟡 警告：x.y —— 描述（不阻断）
```

## 八、汇总席模板（06:30 · 唯一有定稿权）

1. 读三份 `reviews/<date>-*.md` → 合并结论：**任一 🔴 = 该任务回 `[~]`**
2. 应用定稿到 `tasks.md`（**唯一可写方**）
3. 修复可解项 → 跑全量 `pnpm verify`（含 G1–G4）
4. 统一提交三份报告 + `tasks.md` + 修复代码（消息注明 `review:` / `fix:`）
5. `progress.md` 追加汇总条目
6. 汇报：**定稿数 / 驳回数 / 修复数 / verify 状态 / 升级项**
