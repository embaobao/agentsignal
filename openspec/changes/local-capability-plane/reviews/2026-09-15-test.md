- 实现：`src/capability/export.ts` 导出侧剥内部首部用严格正则（name/description 两行形态），产物经 `renderArtifactSkillMd` 重渲染；导入侧 L115 用 `raw.replace(/^---\n[\s\S]*?\n---\n\n/, "")` 剥产物首部后落库。
- 测试：`capability-export.test.ts` L130–154 用**同一正则**对导出 md 自算期望值，与 `loadDetail().body` 逐字比对。
- 判定：若 importApm 漏剥/少剥（首部带进 body），detail.body 含首部 ≠ 期望 → 红；若多剥，同样红。测试对「剥离偏差」双向守卫，真实有效。
- 附注（非缺陷）：detail.body 经 loadDetail 的 mustache 渲染与 updates 拼接，本夹具正文无模板变量、无 UPDATES.md 时 raw==rendered，等价性成立；未来正文含 `{{ }}` 时此断言需另行考虑（现状夹具纯净，不构成问题）。

### b) s02「三路径分别计数互不串扰」——串写是否红？**是，必红。**

- 实现：`src/skills/lifecycle.ts` `bumpSkillMetrics` L172 为键控写入 `parsed.lifecycle.metrics[key] += 1`（key ∈ retrieved/injected 分立类型）；`loader.ts` L144 loadDetail 成功 → injected+1；`verify.ts` L54 verify → use_count+1（独立键）。
- 判定：若 retrieved/injected 串写同键，夹具 2 次 retrieved + 1 次 injected 后共享键=3，`retrieved===2` 与 `injected===1` 双断言皆红。三计数分立回归真实在守。

### c) contract-degrade「L2/L3 带原因」——fake 静默丢 skipped，契约套件拦不拦？**套件本身不拦，场景第二条拦（红）。**

- `contract.ts` L82–84 确有「skipped 条目必须带 reason（D10）」断言，但它只 deploy 到 `hosts()[0]`——本 fake 首宿主是 claude-code → L1，skipped 合法缺省，断言空转；且空数组对逐条遍历断言恒真（vacuous）。
- 真正的拦截在 `contract-degrade.test.ts` L57–69：显式 deploy cursor/gemini，`assert.match(l2.skipped?.[0]?.reason ?? "", /L2/)`——静默丢弃时 `?? ""` 落空 match 失败 → 红。
- 结论：本条测试真实（回退必红），但暴露 **C2 契约套件对多档降级适配器的结构性缺口**：未来接入「ladder=L2/L3 但 skipped=[]」的适配器可过契约套件。建议（非阻塞）：契约套件遍历全部 `hosts()`，或加结构断言「ladder≠L1 ⇒ skipped 非空且逐条带 reason」。
