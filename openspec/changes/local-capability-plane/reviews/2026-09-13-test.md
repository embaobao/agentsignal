## 三个抽查判断（读实现源码验证「实现回退时测试必红」）

### a) schema-defaults「dependencies default 引用隔离」——会红 ✅

- 实现锚点：`packages/protocol/src/skill-schema.ts:82` `.default(() => ({ env: [], bins: [], packages: [] }))`（函数工厂，zod ^4.4.3；行注明示「函数工厂（引用隔离）」）。zod 语义：字面量 default 跨 parse 返回**同一引用**，工厂 default 每次 parse 调用新建。
- 若改回 `.default({ env: [], bins: [], packages: [] })`：a.dependencies 即共享实例，`a.dependencies.env.push("MY_VAR")` 原地污染，b parse 拿到同一数组 → `deepEqual(b.dependencies.env, [])` 立即失败；metrics 用例同理（b.retrieved 变 1 ≠ 0）。**判断：回退 → 红。**

### b) contract-adapter「reconcile 缺失即违约」——真的拒收 ✅（附一条注记）

- 契约侧 contract.ts:103 对 `adapter.reconcile()` **无任何守卫直接 await**——reconcile 被删即 `TypeError: adapter.reconcile is not a function` → 契约 reject → 测试 assert.rejects 通过；若套件日后 try/catch 容忍缺失 → 无 rejection → assert.rejects 红。**判断：套件放松守卫 → 红。**
- 注记（V0 可接受）：拒绝来自 JS 运行时 TypeError 兜底而非契约专属结构化错，且该测试用无 matcher 的 `assert.rejects`——目的上仍确定（该 fake 其余方法全齐，唯一拒绝源就是被删的 reconcile）；A 轨收口时建议换成定向 matcher 或结构化错。
