## 三个抽查判断（读实现源码验证「断言确实能失败」）

### a) artifact-frontmatter「私有层字段零泄漏」——会红 ✅

- 实现锚点：`packages/protocol/src/skill-schema.ts:183` `ArtifactFrontmatterSchema = z.object({ name, description })`（zod 未知键默认剥离）；`packages/cli/src/skills/transcoder.ts:96` `renderArtifactSkillMd` 仅序列化 name/description 两键。
- 若实现改为 `.passthrough()`、把 layers/triggers 等并入产物 schema、或 render 附带私有键：`Object.keys(out)` deepEqual 与 `!md.includes(priv)` 两条断言立即失败。**判断：删除该行为 → 红。**

### b) wiring-hermes「零垃圾：HERMES_HOME 下只应有 SOUL.md」——会红 ✅

- 实现锚点：`packages/cli/src/skills/wiring/snippets.ts:101` `wireMcp` 对 `mcpPath === null` 提前 return（不建目录不写 MCP 文件），rules 兜底走 `injectSoulBlock(soulPath)`（hosts.ts:114 hermes `mcpPath: null`）；`hostStatus` 同样有 null 守卫（snippets.ts:83）。
- 断言是 `readdir(HERMES_HOME)` **deepEqual `["SOUL.md"]`**——wire 路径上任何回归（写 mcp 配置、预建 config.yaml、多建目录）都会使目录条目变化而立即失败，非 contains 式弱断言。**判断：删除该行为 → 红。**

### c) verify-target「旧数组归一 statement=首条」——会红 ✅

- 实现锚点：`packages/cli/src/skills/verify.ts:16-28` `normalizeVerifyTarget`：数组分支 `statement: checks[0]`、空数组→null；schema 侧 `skill-schema.ts:159` union 放行 null/数组；`verifySkill`（verify.ts:67）把归一结果放进返回值。
- 若实现去掉数组分支（返回 null）或改取末条：单测 deepEqual `{statement:"旧一",checks:["旧一","旧二"]}` 与 verifySkill 端到端断言同时失败；若 schema 收紧拒绝 null/数组，「旧技能全链零破坏」用例抛错。**判断：删除该行为 → 红。**
